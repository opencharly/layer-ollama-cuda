**Disposition of the two earlier failing attempts on this PR, stated so it is not read as a
flake dismissal:**

1. The first probe run failed with `could not connect to ollama server` — the pod's GPU gate
   refused to start the server while a co-tenant (strata) held the card. That is the gate
   behaving as designed; its RCA is opencharly/pod-ollama#10. The bed now sets
   `OLLAMA_GPU_MIN_FREE_MIB: "64"` for its own service start (the operator-facing knob) so the
   composition can be checked on a contended host; the gate's REFUSAL path stays proven by
   `probe-gate-refuses-on-gpu` and `ollama-gpu-gate-refuses`, each of which sets its own
   impossible threshold.
2. The following attempts failed at `image-build` with `no space left on device` /
   `ResourceExhausted`. RCA: `~/.cache/charly/registry` had grown to **812 GiB** and the
   sanctioned `charly clean --cache` reclaimed 361 B of it; every build then died on ENOSPC.
   Filed as opencharly/charly#1253, and the cache was cleared with operator approval — after
   which the same build completed green above. The probe base was switched to the upstream
   cachyos digest because the earlier locally-built base lived only in that cache.
